## 1. Decision rule

Blueprint acceptance requires more than code presence. Each exit requires an appropriate combination of source requirement mapping, implementation, migration/API/event contract, automated tests, observability/audit, operational evidence, and owner acceptance. A green unit/SQL test proves the behavior tested, not a live provider connection, UI acceptance, production deployment, capacity certification, or a real DR exercise.

## 3. HLD architecture invariants — design-to-evidence check

The HLD defines logical planes/deployment profiles and cross-cutting invariants that apply across WPs. The following assessment points are release controls, not a replacement for the complete SRS matrix.

| HLD invariant / design area | Evidence currently found | Status and gap |
|---|---|---|
| Source-of-record wins; the model cannot rewrite production truth | Domain-ledger transactions, version guards, audited decisions, should-cost source evidence, operational event reconciliation | **Partial across the whole product.** Verify every AI-assisted write path and every external adapter against the exact domain source-of-record. |
| Policy/identity is outside the model; action via typed tools; fail closed | IAM authorization, AI Tool Gateway registry/schemas/risk/approval/token checks, entitlement re-check, negative unit/SQL tests | **Core paths implemented; full path coverage partial.** Prove deny paths and all production executors per requirement ID. |
| Private-by-default tenant/factory context | RLS/tenant inventory, forced-RLS contracts, tenant/factory FKs and negative isolation tests | **Bounded PostgreSQL surfaces tested; not whole-tenant.** Indirect-owner relations and external object/cache/vector/provider/backup copies still require verification. |
| Evidence before confidence; conflicts, freshness and provenance are explicit | CBB governance, research rights/extraction/citation lineage, growth scenario and forecast-evaluation contracts | **Partial.** Real providers, review UI, source authenticity and statistical calibration/threshold approval remain. |
| No silent learning; evaluated release and rollback | Versioned growth/research releases, CBB rollback receipt, AI evaluation foundations and schema-versioned contracts | **Partial.** Model/prompt/retrieval artifact registry, reproducible shadow comparison and end-to-end rollback in all deployment tiers need proof. |
| Asynchronous work, bounded retry and degraded modes | Outbox/inbox, AI retry scheduling, OT spool/replay, bounded load harness, operational runbook | **Partial.** External bus/edge drivers, queue visibility, provider outage and live degradation acceptance remain. |
| Observability is part of correctness | W3C Trace Context, sampled OTLP HTTP/DB spans, process/database metrics and health probes | **Repository implementation present; production acceptance partial.** Central collector/backend, dashboards, alert delivery, retention and owner-approved SLO are external. |
| Cloud SaaS, dedicated/VPC and approved private/edge topologies preserve security contracts | SaaS deployment-profile/control-plane and OT/edge configuration contracts | **Not fully proven across topology variants.** Run per-tier isolation, residency, operational and migration tests before claiming parity. |
| Backup/DR and recovery are tested rather than inferred | Encrypted backup/restore helper contract, ordered migration/failure CI, load harness contract | **Harness automation only until an actual rehearsal is recorded.** HLD §23 numbers are proposed baselines and require service-owner approval. |
