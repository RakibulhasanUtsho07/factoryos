### Evidence rules

1. An endpoint, migration or markdown document alone is not acceptance evidence. The audit links source, persistence constraints, tests and CI where those exist.
2. A test only proves the behavior actually exercised by that test. SQL catalog/RLS checks do not prove every endpoint denies all foreign-tenant misuse; mock transport does not prove a real provider works.
3. Existing functionality is not counted as newly delivered by this audit.
4. A “Partial” result records the known boundary rather than hiding it in a general completion percentage.
5. Direct priorities are taken from the final SRS row when confidently parsed. Thirty-seven ID priorities still need manual verification; engineering priority labels in the gap register are provisional risk triage, not a substitute for source priority.
6. No production database, customer tenant, OT controller, billing provider, ERP/SFTP endpoint or production monitoring system was changed by this audit.

## 7. Requirement orphan and change-control rules

The following rules apply when the master SRS is imported:

1. **Requirement without implementation:** label NOT IMPLEMENTED or BLOCKED; assign owner, priority, dependency and release disposition.
2. **Requirement without automated/manual acceptance evidence:** label IMPLEMENTATION PRESENT / ACCEPTANCE NOT VERIFIED. Do not convert it to PASS based on a PR merge.
3. **Code or migration without requirement/ADR/defect/control reference:** record its engineering rationale and verify it does not silently alter business policy.
4. **Requirement satisfied by external service:** attach the adapter contract, staging evidence, provider revision and an owner-signed operational acceptance. An injectable interface is not a live provider integration.
5. **Production gate:** record exact SHA, workflow run URLs, migration manifest/result, test output, deployment environment, operator/approver and rollback/forward-fix decision.
6. **Change after audit:** any requirement-affecting source, migration, workflow or adapter change invalidates only the linked evidence rows by default, but the exact SHA and affected row mapping must be regenerated before release.
